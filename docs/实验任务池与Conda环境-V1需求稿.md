# 实验任务池与 Conda 环境 V1 需求稿

**状态：** V1 范围已确认
**产品：** LabDeck  及「我的任务」页面

## 1. 背景与目标

当前「我的任务」页面根据服务器 GPU 采集结果，列出 SSH 用户名与本人相同的 GPU 进程。它反映的是实时运行状态，不能由用户创建，也不保存实验计划、环境和结果。

本需求新增一个由用户自主维护的**实验任务池**，用于整理待做实验、记录运行环境、打开对应的远程工作入口，并回顾实验结果。现有 GPU 进程监控继续保留，与用户维护的任务分开展示。

### 目标

- 用户可以创建、编辑实验任务，并将可运行的任务加入 GPU 等待队列。
- 每项实验可以记录目标服务器、代码目录、数据目录和 Conda 环境。
- 从任务页可以快速打开相关服务器的 VS Code、终端和文件窗口。
- 实验计划、运行记录和实际 GPU 进程之间的含义清楚，不相互冒充。
- 任务在应用重启后仍保留。

### V1 范围边界

- 用户明确点击「保存并排队」或「加入队列」后，LabDeck 才会自动启动该任务的命令。
- 每项排队任务固定使用用户指定的一台服务器；只在该服务器内选择空闲 GPU，不会因无空闲卡而改投其他服务器。
- GPU 空闲状态来自启动前的 SSH 实时采样；系统不锁定或预约 GPU，其他用户仍可能同时使用或抢先占用该卡。
- 不把任务、代码或环境自动迁移、同步到另一台服务器。
- Conda 环境必须已存在且可用；V1 不会自动创建或更新环境来满足排队任务。
- 现有“GPU 实时进程”继续显示采集到的进程，不自动认领为某个实验任务。
- V1 面向当前 Windows 用户的本机数据，不包含多人协作或云端同步。

## 2. 术语和页面结构

- **实验任务：** 用户要完成的一项实验计划，例如“ResNet 基线训练”。
- **实验运行：** 同一实验任务的一次具体尝试，可以有独立参数、运行环境和结果。
- **GPU 实时进程：** 监控服务从服务器采集到的实际进程信息。

「我的任务」页面包含两个视图：

1. **实验任务池**：默认视图，管理用户创建的实验任务。
2. **GPU 实时进程**：保留现有实时 GPU 进程列表，显示进程名、用户名、PID、服务器、GPU、运行时长和显存。

侧边栏数字统计未归档的实验任务，不再将实时 GPU 进程数当作任务池数量。GPU 实时进程数量显示在对应视图内。

## 3. 实验任务数据

新建任务仅要求填写实验名称。其余字段可先留空，任务之后仍可编辑。

| 信息组 | 字段 | 规则 |
| --- | --- | --- |
| 基本信息 | 实验名称 | 必填；列表主标题 |
| 基本信息 | 项目、目标/假设、标签、优先级 | 可选；用于搜索、筛选和整理 |
| 运行位置 | 目标服务器、连接路径 | 可选；绑定服务器 ID 和访问路径 ID |
| 运行位置 | GPU | 任务不预选 GPU；运行开始时自动选择并保存 GPU UUID、编号和型号 |
| 运行筛选 | 最低空闲显存 | 可选，按 GiB 设置；未设置时不增加显存门槛。单次排队时可沿用、调整或清除任务默认值 |
| 代码与数据 | 代码目录、数据目录 | 分开填写；通常是目标服务器上的路径 |
| 运行信息 | 启动命令、环境说明 | 加入队列前必须提供启动命令；仅在用户明确加入队列后执行 |
| Conda 环境 | 环境管理器、环境名或前缀路径、Python 解释器路径 | 详见第 5 节；环境配置属于目标服务器 |
| 时间与状态 | 状态、创建时间、更新时间 | 由任务池维护 |
| 实验结论 | 结果摘要、备注、日志/模型文件路径 | 可编辑；文件路径不代表 LabDeck 已上传或备份文件 |

任务状态为：**待开始、等待 GPU、准备运行、进行中、已暂停、已完成、运行失败、已取消**。已完成、失败或取消的任务可以归档；归档任务可以查看和恢复。

服务器信息通过稳定的服务器 ID 关联。另保存创建时的服务器名称快照供历史显示。服务器被删除后不删除实验记录，但远程快捷操作应提示服务器配置已不可用。

## 4. 实验运行记录

一个任务可以有多次实验运行。V1 每次运行至少记录：

- 运行序号、排队时间、开始时间和结束时间。
- 实际目标服务器、连接路径及自动分配的 GPU。
- 本次运行采用的最低空闲显存门槛；未设置时记录为不限制。
- 本次运行使用的代码目录、数据目录、启动命令和参数备注。
- 实际 Conda 环境名/前缀路径、Python 版本及环境配置文件路径。
- 本次结果摘要、过程备注和日志/产物路径。

用户点击「加入队列」时，LabDeck 创建等待记录。调度器只检查记录中指定的服务器：若没有空闲 GPU，任务保持排队；找到空闲卡后，会重新采样，检查代码/数据路径与 Conda 环境，并通过 SSH 在该卡启动命令。启动时使用 GPU UUID 设置 `CUDA_VISIBLE_DEVICES`。任务启动后由服务器端脱离 SSH 会话运行，标准输出和错误写入远程运行日志；LabDeck 根据远程退出码更新完成或失败状态。应用重启后会恢复排队和跟踪远程运行。

空闲判断不构成资源保证：V1 不创建 GPU 锁或预约，服务器上的其他用户可同时启动任务。GPU 实时进程视图仍独立展示真实采集到的进程。

任务可以设置可选的最低空闲显存（GiB），每次排队都可以沿用任务默认值、临时调整或清除门槛。调度器在 GPU 候选筛选和启动前复查时都会应用本次运行的门槛；指定服务器没有同时满足空闲规则和显存门槛的 GPU 时，任务继续排队并显示原因。未设置门槛的旧任务保持原有筛选行为。该筛选只基于采样时报告的空闲显存，不构成显存预留或防止外部进程抢占的保证。

支持复制实验任务以快速建立超参数或配置变体。复制时保留实验目标、路径和环境作为初始值，不复制任务状态、运行记录、结果和时间。

## 5. Conda 环境需求

Conda 环境是实验任务与运行记录的正式字段，不应只放在自由备注中。环境配置隶属于目标服务器；更换目标服务器后，需要重新检查或重新选择环境。

### 5.1 使用已有环境

- 支持 `conda`、`mamba` 和 `micromamba`。
- 连接目标服务器后，可以读取环境列表并选择已有环境。
- 环境可按名称指定，也可使用绝对前缀路径；路径方式用于用户目录下的自定义环境。
- 允许手动填写环境名、前缀路径和 Python 解释器路径，兼容环境无法自动枚举的情况。
- 提供「检查环境」操作，显示是否存在、解释器路径、Python 版本和最近检查时间。
- 服务器离线或命令失败时，将环境标记为未知/未验证，不删除配置或阻止编辑。

### 5.2 从环境文件创建

- 支持记录目标服务器上的 `environment.yml` 路径，并使用所选管理器创建环境。
- 用户可指定新环境名或前缀路径。
- 创建前显示目标服务器、环境文件、管理器及将执行的命令，由用户主动确认。
- 环境创建过程在终端中可见；创建失败时保留终端输出，任务记录不丢失。
- 已存在的环境只能在用户主动选择「更新环境」并确认后更新。
- 不在新建任务、打开任务或应用启动时自动安装、升级或删除包。

### 5.3 激活和 VS Code

- 任务提供「在终端中激活环境」快捷操作，根据管理器和环境名/前缀生成激活命令。
- 对需要 shell 初始化的 Conda 安装，使用检测到的 Conda 初始化脚本或向用户展示可复制的完整命令；失败时明确提示原因。
- 打开 VS Code 时沿用任务的服务器连接路径和代码目录，并显示该环境的 Python 解释器路径。
- 如果无法通过 VS Code Remote-SSH 自动选择解释器，提供清晰的手动选择指引；不得把“已打开 VS Code”显示成“Conda 已激活”。
- 环境文件路径、Python 版本等信息在每次运行记录中保存快照，避免日后环境变更覆盖历史。

## 6. 主要操作流程

### 新建实验

1. 在实验任务池选择「添加实验任务」。
2. 填写名称，按需要添加项目、实验目标和标签。
3. 保存草稿可暂不指定服务器；要自动运行则必须指定一台真实服务器、代码目录和启动命令。
4. 可配置已有 Conda 环境；加入队列前系统检查该环境是否已安装。
5. 选择「保存并排队」后，任务只在指定服务器等待空闲 GPU。

### 开始实验

1. 用户选择「加入队列」，确认本次代码目录、数据目录、启动命令和可选 Conda 环境；服务器沿用任务指定服务器。
2. LabDeck 周期性采集该服务器的 GPU 状态；无可用卡时任务保持排队。
3. 找到空闲卡后再次采样；通过目录和环境检查后，以 GPU UUID 启动命令。
4. 任务记录保存 GPU、PID、远程运行目录和日志路径；实际 GPU 进程仍由实时进程视图独立显示。

### 完成实验

1. LabDeck 根据远程命令退出码更新运行结果；用户可以补充结果、备注和日志/模型路径。
2. 可在任务完成、失败或取消后再次排队运行。
3. 已完成、失败或取消的任务可归档，之后可搜索和恢复。

## 7. 页面交互需求

### 实验任务池

- 显示待开始、排队/运行中和已完成数量。
- 支持按状态、项目、服务器、标签和优先级筛选，支持名称和目标文本搜索。
- 任务行/卡片至少显示名称、状态、优先级、项目、目标服务器、Conda 环境及最近更新时间。
- 支持新建、编辑、复制、保存并排队、移出等待队列、完成、归档和恢复。
- 任务详情显示实验配置、Conda 环境检查状态和运行记录。
- 为空时提供明确的「新建第一个实验」入口。

### GPU 实时进程

- 保留当前实时指标与跳转 GPU 详情能力。
- 标注服务器数据采集时间及缓存/离线状态。
- 不将计划中的任务显示为正在运行，也不把实际进程自动归到任务名下。

### 快捷操作

- 服务器已绑定且配置可用时，可从任务打开 VS Code、终端和远程文件窗口。
- 未绑定服务器时，开始记录前提示选择服务器和连接路径。
- 排队任务显示等待原因、指定服务器、实际分配 GPU 和远程日志路径。
- 调度器仅使用最新 SSH 采样；不锁卡，必须提示外部进程仍可能占用或抢先使用 GPU。
- 代码目录和数据目录分开显示。更换服务器时提示路径属于服务器本地，需检查是否存在。

## 8. 本地保存与安全

- 任务数据保存在当前 Windows 用户的 LabDeck 本地数据文件中，应用重启后恢复。
- 数据结构加入版本迁移，升级后保留已有服务器、监控、历史和凭据数据。
- 任务内容不存入服务器凭据区；不得保存 SSH 密码、私钥内容、访问令牌等秘密。
- Conda 创建/更新操作在执行前显示目标与命令并要求用户确认。
- 任务删除优先使用归档；如提供永久删除，需明确告知会一并移除其运行记录。
- V1 不提供自动云同步或多人共享；本地备份和跨设备迁移另列后续需求。

## 9. 状态、异常与边界

- 服务器离线：任务仍可查看和编辑；远程操作不可用，并显示连接状态。
- 服务器已删除：保留历史服务器名称和路径，禁用远程操作。
- Conda 管理器未安装、环境不存在或环境文件路径失效：显示检查结果，允许修改配置，不将环境误标为可用。
- GPU 监控快照过期：显示采集时间，禁止将旧空闲状态表述为当前保证。
- 任务没有 GPU：允许记录 CPU 或准备类实验，不强制选择 GPU。
- 任务进程状态由调度器按服务器端 PID/退出码维护；GPU 实时进程仍来自独立采集。两者可能暂时不一致，页面必须明确数据来源。
- 代码不在 NAS 或目标服务器上时，不尝试自动同步；路径仅代表用户记录的位置。

## 10. 验收标准

1. 用户可以不配置服务器就创建任务，并在应用重启后看到该任务。
2. 用户可以为任务指定服务器、连接路径、代码目录、数据目录、启动命令和可选 Conda 环境；GPU 由系统在该服务器内自动选择。
3. 服务器可连接时能检查已有 Conda 环境；不可连接时保留任务并显示未验证状态。
4. 从环境文件创建或更新环境必须经用户明确触发和确认，并能看到执行过程及结果。
5. 加入队列后，无空闲 GPU 时任务保持等待；GPU 空闲且路径/环境检查通过后，启动命令在所指定服务器运行并写入退出码和日志。
6. 运行记录保存服务器、连接路径、自动分配 GPU、环境和参数快照；用户可以查看结果、复制任务、归档和恢复任务。
7. GPU 实时进程继续反映真实采集结果，不会被手动任务状态覆盖。
8. 调度不迁移任务到其他服务器，不锁定或预约 GPU，不执行代码同步，也不提供多人共享。
9. 实验任务池、表单、详情和状态在 ocean、instrument、machineRoom 三种主题下均有可读样式。

## 11. 后续能力（不纳入 V1）

- 自动识别 GPU PID 并由用户确认关联到某次实验运行。
- 多次运行对比、参数表格和指标图表。
- 导出/导入任务及完整本地备份恢复。
- 多 GPU、GPU 显存需求约束、进程停止/重试策略以及对接 Slurm 等集群调度器。
- 多人任务共享与状态协作。
- 明确允许后，在服务器之间同步代码或复用环境。
